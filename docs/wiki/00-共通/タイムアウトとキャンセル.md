APIリクエストのタイムアウト設定とキャンセル処理について説明します。

## 概要

すべての非同期メソッドには以下のパラメータが用意されています。

| パラメータ | 型          | デフォルト値 | 説明                         |
| ---------- | ----------- | ------------ | ---------------------------- |
| `timeout`  | `TimeSpan?` | null         | リクエストのタイムアウト時間 |

| `cancellationToken` | `CancellationToken` | default | キャンセルトークン |

## タイムアウト設定

### 個別リクエストのタイムアウト

各メソッドの`timeout`パラメータでリクエスト単位のタイムアウトを設定できます。

```csharp
// 10秒でタイムアウト
var response = await client.GetRecordsAsync(
    siteId: 456,
    timeout: TimeSpan.FromSeconds(10));
```

### デフォルトタイムアウト

クライアント初期化時に`defaultTimeout`を設定すると、すべてのリクエストに適用されます。

```csharp
var client = new PleasanterClient(
    baseUrl: "https://example.com",
    apiKey: "your-api-key",
    defaultTimeout: TimeSpan.FromSeconds(30));
```

### タイムアウトの優先順位

1. メソッドの`timeout`パラメータ（指定時）
2. クライアントの`defaultTimeout`（未指定時）
3. HttpClientのデフォルト（どちらも未指定時）

## キャンセルトークン

### 基本的な使い方

`CancellationToken`を使用して、実行中のリクエストをキャンセルできます。

```csharp
using var cts = new CancellationTokenSource();

// キャンセル可能なリクエスト
var response = await client.GetRecordsAsync(
    siteId: 456,
    cancellationToken: cts.Token);
```

### 一定時間後の自動キャンセル

```csharp
using var cts = new CancellationTokenSource();

// 10秒後に自動キャンセル
cts.CancelAfter(TimeSpan.FromSeconds(10));

try
{
    var response = await client.GetRecordsAsync(
        siteId: 456,
        cancellationToken: cts.Token);
}
catch (OperationCanceledException)
{
    Console.WriteLine("リクエストがキャンセルされました");
}
```

### 手動キャンセル

```csharp
using var cts = new CancellationTokenSource();

// 別スレッドやイベントハンドラからキャンセル
cancelButton.Click += (s, e) => cts.Cancel();

try
{
    var response = await client.GetRecordsAsync(
        siteId: 456,
        cancellationToken: cts.Token);
}
catch (OperationCanceledException)
{
    Console.WriteLine("ユーザーによってキャンセルされました");
}
```

### タイムアウトとキャンセルの併用

タイムアウトとキャンセルトークンは併用できます。どちらかが先に発生した時点でリクエストが中断されます。

```csharp
using var cts = new CancellationTokenSource();

// ユーザー操作でキャンセル可能にしつつ、30秒でタイムアウト
var response = await client.GetRecordsAsync(
    siteId: 456,
    timeout: TimeSpan.FromSeconds(30),
    cancellationToken: cts.Token);
```

## 注意事項

### クライアント側のキャンセルのみ

CancellationTokenはクライアント側の処理を中断するものであり、プリザンター（サーバー）側の処理を中断させることはできません。

```text
┌─────────────┐       リクエスト        ┌─────────────────┐
│   クライアント  │ ──────────────────────> │   プリザンター    │
│             │                          │    （サーバー）    │
│  キャンセル発生  │                          │   処理継続中...   │
│      ↓      │       レスポンス         │                  │
│   待機中断    │ <── （受信しない） ──── │   処理完了        │
└─────────────┘                          └─────────────────┘
```

つまり、以下の点に注意が必要です。

- キャンセル後もサーバー側ではリクエストの処理が継続される可能性がある
- レコードの作成・更新・削除などの操作は、キャンセルしてもサーバー側で実行される可能性がある
- キャンセルはレスポンスの待機を中断するだけで、サーバーへの通信が届いていれば処理は実行される

### 例外処理

タイムアウトやキャンセルが発生した場合、例外がスローされます。

```csharp
try
{
    var response = await client.GetRecordsAsync(
        siteId: 456,
        timeout: TimeSpan.FromSeconds(5),
        cancellationToken: cts.Token);
}
catch (OperationCanceledException ex)
{
    // タイムアウトまたはキャンセルによる中断
    Console.WriteLine($"操作がキャンセルされました: {ex.Message}");
}
catch (TaskCanceledException ex)
{
    // タイムアウトによる中断（HttpClientから発生）
    Console.WriteLine($"タイムアウトしました: {ex.Message}");
}
catch (HttpRequestException ex)
{
    // ネットワークエラー
    Console.WriteLine($"通信エラー: {ex.Message}");
}
```

### リソースの解放

`CancellationTokenSource`は`IDisposable`を実装しているため、使用後は適切に破棄してください。

```csharp
// using ステートメントを使用（推奨）
using var cts = new CancellationTokenSource();

// または明示的にDisposeを呼び出す
var cts = new CancellationTokenSource();
try
{
    // 処理...
}
finally
{
    cts.Dispose();
}
```

### 長時間実行される操作

大量のレコードを処理する場合など、ループ内で定期的にキャンセルをチェックすることを推奨します。

```csharp
using var cts = new CancellationTokenSource();

foreach (var siteId in siteIds)
{
    // キャンセルがリクエストされていれば例外をスロー
    cts.Token.ThrowIfCancellationRequested();

    var response = await client.GetRecordsAsync(
        siteId: siteId,
        cancellationToken: cts.Token);

    // 処理...
}
```
